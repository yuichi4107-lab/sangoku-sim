## 備考列から発掘された cap_rule 種別

| 表記 | 意味 | スキーマ対応 |
|---|---|---|
| `（上限X%）` | 通常の％上限 | `fixed_percent` 既存 |
| `（上限X%・共有）` | **複数スキルで同じ上限プールを共有** | **新規 `shared_cap_group` 必要** |
| `（上限X%・非共有）` | 明示的に非共有 | 既存 `fixed_percent` |
| `（累加不可）` | **同種スキルの内1つしか効かない（合算しない）** | **新規 `non_stackable` 必要** |
| `（上限累加可、1スキル上限X%）` | スキル個別上限＋全体スタック可 | **新規 `per_skill_cap` 必要** |
| `（上限無し）` | 明示的に上限なし | 既存 `no_cap` |
| `(下限X%、上限Y%)` | 上下限ペア | **新規 `bounded` 必要** |
| `馬スキル時上限X%` | **条件付き上限** | **新規 `conditional_cap` 必要** |
| `典韋・曹仁の80%・共有` | **特定武将と上限プール共有** | shared_cap_group の specific 用 |
| `味方残存兵士率x16.5%` | 動的基準値 | 既存 `ratio_of_base` 拡張 |

## xlsx で発見された主要な新概念

### 1. 配置（slot stat）
各武将に `統率 / 武力 / 知性` のいずれかが割り当てられる。これは「どのスロット位置に置けるか」を示す。玄呂蒙だけ「武力/知性」両用。
→ スキーマに `slot_stat` フィールド追加が必要。

### 2. 列D「上限」の値（要解釈確認）
2.5, 3, 2.74, 0, ー など。これは何の値ですか？
- 案A) 武将の「戦力評価点」or プレイヤーの主観優先度
- 案B) ゲーム内の何らかの上限値
- 案C) 突破段階で得られる軍団枠？
→ ユーザーに確認したい

### 3. 共有cap（連帯上限）
複数の武将のスキル間で**1つの上限プールを共有**する。
- 例: 玄孫権「連撃20%減（上限50%・共有）」と関平「連撃馬部隊数×5%減（上限50%・共有）」が同じプールを共有
- 例: 王双「（典韋・曹仁の80%・共有）」のように**特定武将名による紐付け**もある
→ スキーマで `cap_group_id` のような共有識別子が必要。

### 4. 累加不可（non-stackable）
複数同種スキル時、**1つだけが効く**（最大値採用？要確認）。
- 例: 玄大喬「ダメ15%減（累加不可）」、玄許褚「ダメ15%減（累加不可）」が両方編成にあると合算されず1つ分だけ効く

### 5. 馬技スロット
集結シートに「馬技」列が出てくる。HANDOFF の「馬・武将スキル」と一致。
→ 兵科とは別軸の「乗り換え可能スキル枠」？

### 6. 副将スロット
集結シートに「副将」列。3将/部隊 とは別の概念に見える。

### 7. 備考の【装備】記法
「【装備】敵貫通5%減（累加不可）」のように装備限定効果が記載。
→ スキーマの `by_equipment` 配列とは別概念。装備強化で**新規スキル効果が出現**するケースに対応する必要。
