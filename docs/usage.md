# 三国覇王戦記 編成シミュレーター 使い方ガイド

## 1. システムの全体構成

```
┌─ メインシミュレータ (index.html) ──────────────┐
│  ・武将所持登録                                  │
│  ・編成構築（4プレイヤー × 8軍団）              │
│  ・スキル属性マトリクス・上限プール集計         │
│  ・ユーザー単位のJSONインポート/エクスポート    │
│  ・グループ同期（解錠後利用可）                 │
└──────────────────────────────────────────────────┘

┌─ 友人配布用ツール (register.html) ──────────────┐
│  ・スマホ最適化、所持入力に特化                  │
│  ・JSONエクスポート → 依頼者に送信              │
└──────────────────────────────────────────────────┘
```

## 2. 個人モード（あなた専用）の使い方

### 武将所持を登録する

1. 画面右側の **「武将一覧」** から、所持している武将の **所持チェック** を入れる
2. 各武将の育成段階を入力:
   - **3突 / 4突**: どちらか一方にチェック（突破段階）
   - **4装**: 装備完成済みならチェック
   - **印**: 将印枚数（0〜5）
3. 一括設定: 表示中の武将に対し「所持/3突/4突/4装」を一括で適用

### 編成を組む

1. 画面中央の **編成エリア** に8軍団分の枠が並ぶ
2. プレイヤータブで対象プレイヤーを切り替え
3. 軍団ごとに **兵種** を選択（騎兵/歩兵/弓兵/戦車）
4. 各軍団の5枠（主将+副将4枠）に武将を割り当て
5. 集結時の共通優先属性（第一/第二）を上部で指定
6. **「クイック選別」** ボタンで自動編成も可能

### 集計結果を確認する

編成下部に以下が表示:

- **属性マトリクス**: 攻撃/防御/連撃/抵抗/貫通/シールド/貫通抵抗の符号付き合計をスコープ別（集結/軍団/角陣/自部隊）に集計。セルクリックで詳細展開
- **上限プール状況**: cap ルール別の充足率・余裕量・候補武将提示
- **cap_rule 別集計**: 詳細な合計値
- **スキル詳細**: 武将別の解像度の高いブレイクダウン

## 3. 友人配布用ツールの使い方

### 友人への案内

以下のテンプレを使って案内してください:

```
お疲れさまです。三国覇王戦記の武将所持状況を集計したく、ご協力ください。

下記URLをスマホ/PCで開いて入力をお願いします。
👉 https://yuichi4107-lab.github.io/sangoku-sim/register.html

【手順】
1. 名前を入力
2. 所持している武将にチェック + 段階入力（3突/4突/4装/印）
3. 「📤 JSONエクスポート」ボタンを押す
4. ダウンロードされたファイルを私に送ってください

入力途中で閉じても自動保存されるので、何度に分けてもOKです。
```

または index.html 上部の **「📱 QR」ボタン** で QR コードを表示して読み取ってもらえます。

### 友人側の操作

- 名前入力 → 武将カードで所持＋段階チェック → 「📤 JSONエクスポート」
- 入力途中の状態はブラウザに自動保存
- 過去にエクスポートしたファイルがあれば「📥 既存JSONを読込」で続きから編集可能

### あなた側で取り込み

1. 受信した `sangoku_user_{名前}_{日付}.json` を準備
2. index.html の **「ユーザーをインポート」** をクリック
3. ファイルを複数選択可能（50人分まとめて取込OK）
4. 同名プレイヤーがいた場合は上書き確認ダイアログ
   - OK → 既存ユーザーの所持データを上書き
   - キャンセル → スキップ

## 4. ユーザー単位のインポート/エクスポート

### エクスポート（既存登録済みプレイヤーを出力）

1. index.html の **「ユーザーをエクスポート」** をクリック
2. モーダルで対象プレイヤーを選択（全選択/全解除ボタンあり、初期は全選択）
3. 「エクスポート」→ 各プレイヤーごとに JSON ファイルがダウンロード

### インポート

上記「友人側で取り込み」と同じ。register.html 由来でも、自分のエクスポート由来でも同じスキーマ（`sangoku_user_v1`）。

## 5. グループ同期機能（クラウド共有）

### 概要

複数デバイス（PC・スマホ）で **同じ状態を共有** したい場合、または **複数人で同時編集** したい場合に使用。  
Google Apps Script + Google Sheets をバックエンドとして利用。

### 解錠方法（初回のみ）

1. 画面下端の **「⚙️」ボタン** をクリック
2. アクセスコード入力 → **`sangoku2026`** を入力
3. 解錠完了。以降はそのデバイス／ブラウザで常時表示

### 使い方

解錠後、フッター上に表示される **「🔓 グループ同期」パネル**:

| ボタン | 動作 |
|---|---|
| **⬇️ クラウドから取得** | クラウド上の最新データでこの端末を上書き |
| **⬆️ クラウドへ保存** | 現在のローカル状態をクラウドへ送信（他端末・他メンバーに反映） |
| **ライブ同期(5秒)** | ONにすると5秒ごとに自動取得、他端末の変更を即反映 |

### 推奨フロー

#### 初回セットアップ
1. **管理者がローカルでデータを整える** → 「⬆️ クラウドへ保存」で初期化
2. **他メンバーが解錠 → 「⬇️ クラウドから取得」** で初期データ取得
3. 全員が **「ライブ同期 ON」** で日常運用

#### 日常運用
- 編集後は必ず **「⬆️ クラウドへ保存」** を押す（ライブ同期ONでも自動アップロードはしない）
- 他メンバーの更新はライブ同期ONなら自動で反映される
- ライブ同期OFFなら手動で「⬇️ クラウドから取得」

### 注意点

- **権限**: 全員が全員のデータを編集可能（last-write-wins 方式）
- **同時編集**: 同時刻に複数人が編集すると後勝ち。可能なら時間帯を分ける
- **解錠状態の管理**: アクセスコードを知らない人には機能自体が見えない
- **ロック解除**: 「ロックに戻す」ボタンで再ロック可能、再解錠にコード入力必要

## 6. データ管理

### ローカル保存（localStorage）

- メインシミュ: キー `sangoku_sim_v06`
- 登録ツール: キー `sangoku_register_v1`
- グループ解錠状態: キー `sangoku_group_unlocked_v1`
- ライブ同期ON状態: キー `sangoku_live_sync_v1`

### バックアップ・移行

- **個人データのバックアップ**: 「ユーザーをエクスポート」で定期的に JSON 保存推奨
- **新端末への移行**: 旧端末で「ユーザーをエクスポート」→ 新端末で「ユーザーをインポート」
- **グループ機能利用時**: クラウドが正、ローカルは作業端末用キャッシュ

## 7. トラブルシューティング

| 症状 | 対処 |
|---|---|
| 「データロードエラー」表示 | ハードリロード（Ctrl+Shift+R）、それでも駄目ならブラウザキャッシュ削除 |
| ⚙️ ボタンを押しても反応なし | F12 開発者ツール → Console でエラー確認 |
| グループ同期で「取得失敗」 | GAS Web App URL が変わった可能性。管理者に連絡 |
| 友人JSON取り込みでエラー | スキーマが `sangoku_user_v1` か確認、JSONの破損確認 |
| 編成が壊れた | 過去のエクスポートJSONからインポートで復旧 |
| 武将データが古い | GitHub Actions が generals.yaml の更新時に自動再ビルド。1〜2分待ってリロード |

## 8. データ更新フロー（管理者向け）

新しい武将データ追加:
1. `generals.yaml` を編集（または スクショ取込で自動更新）
2. `python scripts/classify_skill_attributes.py` で属性再分類
3. `python scripts/inline_data_to_html.py` で index.html / register.html に埋め込み
4. git commit & push → GitHub Actions で自動再ビルド → GitHub Pages に反映

GitHub Actions が走るのは以下のファイル変更時:
- `generals.yaml`
- `scripts/classify_skill_attributes.py`
- `scripts/inline_data_to_html.py`
- `.github/workflows/build.yml`
