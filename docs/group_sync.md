# グループ同期機能 詳細ガイド

複数のデバイス・複数のメンバーで **同じデータをクラウド経由で共有・編集** する機能の使い方説明。

## 1. この機能で何ができるか

### ユースケース A: 1人で複数端末を使う

```
[あなたのPC]  ←─ クラウド ─→  [あなたのスマホ]
              共通データ
```

PCで編成を組んで、スマホでも同じ状態を確認・編集できる。  
通勤中にスマホで武将所持を更新 → 帰宅後PCでそのまま編成検討。

### ユースケース B: 仲間内で共同編集

```
[あなた]
  ↕
クラウド ↔ [メンバーA] ↔ [メンバーB] ↔ [メンバーC]
   ↕
[共通の所持・編成データ]
```

複数人が同じ編成データを編集。誰かが武将を追加・編成を変更すると、他の人の画面にもライブで反映される。集結戦の事前打ち合わせなどに活用。

## 2. 全体の流れ（はじめに）

```
1. 解錠する（コード入力）   ← 初回のみ
       ↓
2. クラウドへ初期データを送る ← 管理者（あなた）が一度実施
       ↓
3. メンバーがクラウドから取得  ← 各メンバーが1回
       ↓
4. ライブ同期 ON で日常運用    ← 全員
```

## 3. 用語

| 用語 | 意味 |
|---|---|
| **ロック / 解錠** | グループ機能の表示を切り替える。アクセスコードで解錠 |
| **クラウド** | Google Apps Script + Google Sheets で動くデータ保管庫 |
| **⬆️ クラウドへ保存（push）** | 自分のローカル状態をクラウドに送り、全員に共有 |
| **⬇️ クラウドから取得（pull）** | クラウドの最新状態を取ってきて自分のローカルを上書き |
| **🔗 同期モード** | 通常の動作モード（保存ボタンは緑色）|
| **🧪 試作モード** | 切り離して試したい時用（保存ボタンが警告色＋確認ダイアログ）|
| **last-write-wins** | 同時編集時は「最後に保存した人」のデータが残る |

## 4. 初回セットアップ手順

### 管理者（あなた）の作業

#### Step A-1: グループ機能を解錠

1. シミュレーター画面の最下端にある **⚙️ ボタン** をクリック
2. アクセスコード入力欄に **`sangoku2026`** と入力 → OK
3. フッターの上に **緑色の「🔓 グループ同期」パネル** が出現

#### Step A-2: ローカルデータを準備

クラウドに送る初期データを整える:
- 個人モードで武将所持・編成を入力（自分自身の分）
- または register.html 経由で集めた友人データを「ユーザーをインポート」で取り込み済み

#### Step A-3: クラウドへ初期データをアップロード

1. グループ同期パネル の **「⬆️ クラウドへ保存」** をクリック
2. 「保存完了 HH:MM:SS」と表示されれば成功
3. これでクラウド上にデータが入った

### メンバー（友人）の作業

#### Step M-1: シミュレーターを開いて解錠

1. 管理者から共有された URL を開く: https://yuichi4107-lab.github.io/sangoku-sim/
2. ⚙️ ボタン → アクセスコード `sangoku2026` を入力
3. グループ同期パネル表示

#### Step M-2: クラウドからデータ取得

1. **「⬇️ クラウドから取得」** をクリック
2. 確認ダイアログ → OK
3. 「取得完了」と表示されればローカル状態がクラウドと同じに

## 5. モード切替（同期モード / 試作モード）

通話しながら共同編集している最中などに、**自分だけで切り離して試したい時** は試作モードを使う。

```
[🔗 同期モード]
  通常運用。⬆️ クラウドへ保存 はそのまま実行
        ↕ ボタン1タップで切替
[🧪 試作モード]
  ⬆️ クラウドへ保存 ボタンが警告色（赤）になり、
  押すと「試作中の内容を本番に反映しますか？」と確認ダイアログ
```

切替は **モードボタン1タップ**。データには影響しない（状態を変えるだけ）。

### 使い分け例

| 場面 | モード |
|---|---|
| 通常の共同編集 | 🔗 同期モード |
| 自分だけで試しに編成を組んでみる | 🧪 試作モード |
| 試作内容を本番に反映したい | 試作モードのまま「⬆️ クラウドへ保存」→ 確認OK |
| 試作内容を破棄して同期に戻る | 🔗 同期モードに戻す → 「⬇️ クラウドから取得」 |

## 6. 日常運用パターン

### パターン1: 編成を編集して全員に共有したい

1. 編成画面で武将配置を編集
2. 編集が終わったら **「⬆️ クラウドへ保存」** を押す
3. 他メンバーは自身で **「⬇️ クラウドから取得」** で最新を取得

> 自動同期はありません。**全て手動操作**です。

### パターン2: 他メンバーの最新状態を見たい

手動で **「⬇️ クラウドから取得」** を押す。

### パターン3: 自分のデバイスを切り替えたい

1. 旧端末で **「⬆️ クラウドへ保存」**
2. 新端末で解錠 → **「⬇️ クラウドから取得」**
3. 続きから作業可能

### パターン4: 通話しながら共同編集中に、自分だけで試したい

1. 🔗 同期モード → タップで **🧪 試作モード** に切替
2. 自由に編集（保存しても警告ダイアログが出るので誤反映防止）
3. 採用したい場合 → 試作モードのまま「⬆️ クラウドへ保存」→ 確認OK
4. 破棄したい場合 → 🔗 同期モードに戻す → 「⬇️ クラウドから取得」

### パターン4: 編集中に他の人と被りそう

- 「今から編集します」とチャットで宣言
- 編集中はライブ同期OFFを推奨（自分の入力を上書きされない）
- 編集完了後 push → 他メンバーに反映

## 6. データ衝突への対処

### 同時編集が起きるとどうなるか

A さんと B さんが同時刻に違う編集を保存した場合:
- 後に push したほうのデータがクラウドに残る
- 先に push したほうの編集は **失われる**

### 防ぎ方

- **編集前に必ず pull** して最新を取得してから編集する
- 大きな変更は事前にメンバーに告知
- ライブ同期ONなら他メンバーの更新が自動で入ってくるので、変な状態になりにくい

### もし大切なデータが消えた場合

- Google スプレッドシート（管理者の Drive）の履歴から復旧可能
- 管理者: シート → 「ファイル」→「変更履歴」→「変更履歴を表示」→過去の状態に戻せる

## 7. アクセス制御とセキュリティ

### 誰がグループ機能を使えるか

- アクセスコード（`sangoku2026`）を知っている人だけ
- 解錠状態は **デバイス・ブラウザごと** に保存される
- ロックに戻したい場合は「ロックに戻す」ボタン

### 誰がクラウドにアクセスできるか

- Apps Script Web App URL を知っている人なら誰でも
- URL は アクセスコードを知った人（解錠した人）にだけ実質的に届く
- URL 自体は index.html のソースコード内にあるが、解錠UIを通らないと使用されない

### コードを変更したい場合

`index.html` のソース内の以下の値を変更:
```javascript
const GROUP_PASSPHRASE = 'sangoku2026';
```
変更後 push → 全員にハードリロードを依頼。

## 8. トラブルシューティング

| 症状 | 原因 | 対処 |
|---|---|---|
| 「取得失敗 HTTP 4xx」 | Web App の権限設定が「全員」になっていない | 管理者が Apps Script デプロイ設定確認 |
| 「取得失敗 HTTP 5xx」 | Google 側の一時的エラー | 数秒後リトライ |
| クラウドが空 | 誰もまだ push してない | 管理者が初回 push 必要 |
| ライブ同期しても反映されない | push を忘れている | 編集者が手動で「⬆️ クラウドへ保存」を押す必要あり |
| 編集中に勝手にデータが変わった | ライブ同期ONで他メンバーが push した | OK、それが意図された動作 |
| ⚙️ クリックしても反応なし | キャッシュが古い | ハードリロード（Ctrl+Shift+R） |
| 自分の編集が消えた | 他メンバーの push に上書きされた | スプレッドシートの履歴から復旧 |

## 9. 内部仕様（参考）

### データ構造

クラウド側（Google Sheets セル B1）に以下のJSONを保存:

```json
{
  "schema": "sangoku_group_v1",
  "users": [{ "id": 1, "name": "あなた" }, ...],
  "ownerships": {
    "1": { "曹操": { "owned": true, "breakthrough": 4, ... }, ... },
    "2": { ... }
  },
  "activeUserId": 1,
  "formations": [...],
  "priority": { "pri1": "攻撃", "pri2": "連撃" },
  "aggMode": "formation"
}
```

### API

- **GET**: 共有データを返却。レスポンスは `{ ok, data, updated_at }`
- **POST**: ボディの JSON 全体を Sheet に保存。レスポンスは `{ ok, updated_at }`
- 並行書き込み: GAS の LockService で直列化（15秒待ちロック）

### ライブ同期の挙動

- 5秒ごとに GET
- レスポンスの `updated_at` が前回と異なれば「他人の更新あり」と判定
- データを applySharedPayload() でローカルに反映、UI 再描画

### ローカル保存

- `sangoku_group_unlocked_v1`: 解錠状態（"1" or 削除）
- `sangoku_live_sync_v1`: ライブ同期ON状態（"1" or 削除）
- 既存の `sangoku_sim_v06`: ローカル状態（個人モード時のキャッシュ）

## 10. よくある質問

**Q. グループ機能を解錠したら、個人モードのデータはどうなる？**  
A. 何もしなければそのまま。「⬇️ クラウドから取得」を押すと、ローカルがクラウドの内容で上書きされる。事前に「ユーザーをエクスポート」しておけば復旧可能。

**Q. ライブ同期中に自分が編集すると、他メンバーにすぐ送られる？**  
A. いいえ。**「⬆️ クラウドへ保存」を押すまでは自分のローカルにしか入りません。** 手動 push が必要。

**Q. メンバーの登録には何が必要？**  
A. 何も登録不要。URL を共有してアクセスコードを伝えるだけ。匿名認証も使っていない。

**Q. データの上限はある？**  
A. Google Sheets セル1個に約5万文字まで。現在の構成（武将157体×プレイヤー数）なら数万文字なので余裕。150人くらいまでは問題なし。

**Q. 履歴は残る？**  
A. Google Sheets 自体の変更履歴で確認可能（管理者の Drive から「変更履歴を表示」）。ただしJSON文字列なので人間には読みにくい。

**Q. オフラインでは使える？**  
A. 解錠UIや push/pull は使えないが、ローカル編集は可能（個人モードと同じ動作）。オンラインに戻ってから手動 push。
